## 二、三把尺，一個基準

基準**不是另一把尺，是人**。先把 40 個答案逐字讀完、人工標成三類，
標完才准跑程式：

```
正確    規章怎麼規定，答案就怎麼說（用詞可以完全不同）
不完整  沒有講錯，但漏掉問題直接問到的要件
錯誤    與規章相牴觸，或答反了
```

標註原則寫死三條，**先寫再標，不准邊標邊改**：

1. 「沒說」不等於「說錯」——問「會不會被記過」，答「不會，先書面提醒」就是對的
2. 答反了就是錯，不管關鍵詞多齊全
3. 問題沒問到的細節不列入要求

三把尺：

| 代號 | 尺 | 怎麼判 | 每個答案幾次 LLM |
|---|---|---|---|
| A | 關鍵事實比對（`grader.grade`） | `facts` 子字串比對，`forbid` 命中即扣 | 0 |
| B | 逐項 rubric（`rubric_day18.json`） | 每個 checkpoint 問一次：符合／未提及／相反 | 2~4 |
| C | LLM 整體裁判 | 給題目＋條文原文＋答案，回三類判定＋理由 | 1 |

**尺 B 的關鍵設計：checkpoint 分 required 與 bonus。**
Day 17 的四個誤殺全是因為我把「條文裡有的事實」當成「答案必須包含的事實」。
rubric 把這件事顯式化：306 的「申誡」是 bonus（沒說不扣分，說反了才扣），
「不會直接記過」才是 required。**這個分類就是 Day 17 那一課的程式碼形式。**

三類判定的聚合規則：

```
任一 required 判「相反」          → 錯誤
任一 bonus   判「相反」          → 錯誤   （說錯了就是錯，不管必不必要）
否則任一 required 判「未提及」    → 不完整
否則                             → 正確   （bonus 未提及不扣分）
```

## 三、裁判自己要怎麼驗（今天的重點在這節，不在第二節）

換成 LLM 當裁判，等於把判對錯外包給另一個會出錯的模型。
**沒量過這四項的裁判不准上線。**

### 3-1 自我一致性

同一批答案、同一個 prompt、temperature=0，跑 5 遍，看會不會改口。

⚠️ 這一項踩到一個坑，值得寫進文章：`rag_core.chat()` 有快取，
而快取 key 是 model＋messages 的雜湊。**同一個 prompt 問五次會命中五次快取，
一致率必然是 100%——那是快取的一致性，不是模型的。**
所以今天替 `chat()` 加了 `use_cache=False`，只給這一節用。

一個有快取的實驗看起來永遠很穩，這件事本身就是本系列到今天為止的盲點。

### 3-2 長度偏誤

同一題，正確但極短的答案 vs 正確但冗長的答案，尺判得一樣嗎？
Day 17 的 305 題就是被「太短」誤殺的，而模型實際會寫的就是短答案。

### 3-3 位置偏誤

整體裁判的 context 裡兩條條文對調順序，判定會不會變。
最便宜的一項，而且最常爆。

### 3-4 負向對照（`probes_day18.json`）

不靠模型隨機產生，直接手寫四種答案餵進去，看尺攔不攔得住：

| 變體 | 內容 | 期望判定 |
|---|---|---|
| `verbatim` | 必要條文原文直接拼接 | 正確 |
| `terse` | 一句話的正確答案 | 正確 |
| `verbose` | 正確但冗長、夾雜無關條文 | 正確 |
| `negated` | 與 `terse` 只差一個否定詞 | **錯誤** |

Day 17 的自我檢查只做了 `verbatim` 這一列，所以它 8 題全過，
然後什麼都沒發現。**只測「照抄原文會不會過」的自我檢查，
等於只考自己會的那題。** `negated` 這一列才是今天真正的考題。

## 四、招牌表的骨架

```
| 尺 | 與人工標註一致 | 誤殺（人判對→尺判錯） | 放水（人判錯→尺判對） | 成本 |
|----|---------------|--------------------|--------------------|------|
| A 關鍵事實比對 |    /40 |   |   | 0 元 |
| B 逐項 rubric  |    /40 |   |   |      |
| C LLM 整體裁判 |    /40 |   |   |      |
```

**誤殺與放水一定要分開列。** 一把誤殺多的尺讓你去修沒壞的東西；
一把放水多的尺讓你以為系統好了。這兩種錯的代價完全不同，
合成一個「準確率」就看不見了。

預期（跑完回來對）：A 的誤殺會很難看、放水至少 2 筆；
B 應該兩邊都收斂；C 的一致率可能跟 B 接近，但 3-1 的一致性會比 B 差——
因為整體判定要模型一次做完所有取捨，而 rubric 把問題切小了。
**如果 C 反而更穩，那我這個假設就要在文章裡認錯。**
